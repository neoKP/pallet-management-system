# คู่มือจัดการ Telegram Bot Token

## สรุปสั้น ๆ

Token เดิมถูกเขียนไว้ในโค้ดและ **commit ขึ้น git ไปแล้ว** (commit `f7599a4`)
ใครที่เห็นโค้ดนี้ หรือเปิด DevTools ในเบราว์เซอร์ ก็เอา token ไปใช้ได้

**สิ่งที่ต้องทำ: ยกเลิก token เดิมที่ @BotFather — ใช้เวลา ~10 นาที**

---

## เปรียบเทียบให้เห็นภาพ

Token เหมือน **กุญแจบ้าน** ที่ถูกถ่ายรูปลงอินเทอร์เน็ตไปแล้ว

การลบรูปออกไม่ช่วยอะไร เพราะคนที่บันทึกรูปไว้ยังทำกุญแจปลอมได้
**ต้องเปลี่ยนลูกบิดใหม่** = ยกเลิก token เดิมแล้วขอใหม่

---

## ✅ ตอนนี้ token อยู่ฝั่งเซิร์ฟเวอร์แล้ว

| วิธี | กัน token หลุดเข้า git | กันผู้ใช้อ่านจากเบราว์เซอร์ |
|---|---|---|
| ฝังในโค้ด (แบบเดิม) | ❌ | ❌ |
| ตัวแปร `VITE_*` | ✅ | ❌ |
| **ผ่าน API route (ใช้อยู่)** | ✅ | ✅ |

### กฎเหล็กที่ต้องจำ

> **ห้ามใส่ `VITE_` นำหน้าตัวแปรที่เป็นความลับเด็ดขาด**

Vite จะฝังตัวแปรที่ขึ้นต้นด้วย `VITE_` ลงในไฟล์ JS ที่ส่งให้เบราว์เซอร์
ผู้ใช้กด F12 → Sources ก็อ่านเจอทันที

ตอนนี้ token เก็บเป็น `TELEGRAM_BOT_TOKEN` (ไม่มี `VITE_`) และถูกอ่านโดย
`api/telegram/send.ts` ซึ่งรันบนเซิร์ฟเวอร์ของ Vercel เท่านั้น

**ตรวจสอบได้:** หลัง build แล้ว `grep` หา token ใน `dist/` จะไม่พบ

## ขั้นตอนที่ต้องทำเอง (~10 นาที)

### 1. ยกเลิก token เดิม (สำคัญที่สุด)

1. เปิดแอป Telegram
2. ค้นหา **@BotFather** — ต้องมีเครื่องหมายยืนยันสีฟ้า
   ⚠️ มีบอทปลอมชื่อคล้ายกันเยอะ ตรวจให้ดี
3. พิมพ์ `/mybots`
4. เลือกบอทของระบบพาเลท
5. กด **API Token**
6. กด **Revoke current token**
   → token เดิมใช้ไม่ได้ทันที ใครที่ขโมยไปก็ใช้ไม่ได้
7. Telegram จะแสดง **token ใหม่** ให้ — คัดลอกเก็บไว้

### 2. ใส่ token ใหม่ในระบบ

เปิดไฟล์ `.env.local` ที่โฟลเดอร์โปรเจกต์ แล้วใส่ค่า:

```
TELEGRAM_BOT_TOKEN=ใส่_token_ใหม่_ตรงนี้
TELEGRAM_ALLOWED_CHAT_IDS=-1002778234464
```

⚠️ **ห้ามใส่ `VITE_` นำหน้า** — จะทำให้ token หลุดไปอยู่ในเบราว์เซอร์ผู้ใช้

### 3. ตั้งค่าบน Vercel ด้วย

ไฟล์ `.env.local` อยู่แค่ในเครื่อง เว็บจริงมองไม่เห็น
ต้องตั้งค่าแยกใน Vercel Dashboard (ดูหัวข้อ "ตั้งค่าบน Vercel" ด้านล่าง)

### ⚠️ การทดสอบในเครื่อง ต้องใช้คำสั่งที่ถูกต้อง

| คำสั่ง | เสิร์ฟหน้าเว็บ | เสิร์ฟ API route | แจ้งเตือนทำงาน |
|---|---|---|---|
| `npm run dev` | ✅ | ❌ | ❌ (ได้ 404) |
| `npm run dev:vercel` | ✅ | ✅ | ✅ |

`npm run dev` ใช้ Vite ล้วน ซึ่งไม่รู้จักโฟลเดอร์ `api/`
ถ้าต้องการทดสอบการแจ้งเตือนในเครื่อง ให้ใช้ `npm run dev:vercel`
(ครั้งแรกจะให้ล็อกอินและผูกโปรเจกต์ก่อน)

ถ้าใช้ `npm run dev` ธรรมดา ระบบยังทำงานได้ปกติทุกอย่าง
แค่ไม่ส่งแจ้งเตือน และจะขึ้นคำเตือนใน Console บอกวิธีแก้

### 4. ทดสอบว่าส่งได้

บันทึกรายการเคลื่อนย้าย 1 รายการ แล้วดูว่ามีข้อความเข้า Telegram ไหม

ถ้าไม่เข้า → เปิด DevTools (F12) แท็บ Network ดู request ที่ยิงไป
`/api/telegram/send` ว่าตอบกลับมาเป็นอะไร

| รหัส | แปลว่า |
|---|---|
| 200 | ส่งสำเร็จ |
| 403 | chat id นี้ไม่อยู่ใน `TELEGRAM_ALLOWED_CHAT_IDS` |
| 503 | ยังไม่ได้ตั้งค่า env บน Vercel |
| 502 | Telegram ปฏิเสธ (token ผิด หรือบอทไม่ได้อยู่ในกลุ่ม) |

## ถ้ายังไม่ใส่ token จะเป็นยังไง

ระบบ **ทำงานได้ปกติทุกอย่าง** แค่ไม่ส่งการแจ้งเตือน Telegram

เราออกแบบให้การแจ้งเตือนล้มเหลวไม่กระทบการบันทึกพาเลท เพราะงานหน้างานสำคัญกว่า

ตอนเปิดเว็บจะเห็นคำเตือนใน Console แค่นั้น

## 🏗️ สถาปัตยกรรมปัจจุบัน

```
ก่อน:  เบราว์เซอร์ ──(มี token)──> Telegram API
                    ↑ ใครเปิด DevTools ก็อ่าน token ได้

ตอนนี้: เบราว์เซอร์ ──(ไม่มี token)──> /api/telegram/send ──(มี token)──> Telegram
                                        ↑ รันบนเซิร์ฟเวอร์ Vercel
                                          + ล็อกปลายทางไว้ด้วย
```

ไฟล์ที่เกี่ยวข้อง: `api/telegram/send.ts`

### การป้องกันที่ใส่ไว้

| ป้องกันอะไร | วิธี |
|---|---|
| token หลุดถึงเบราว์เซอร์ | เก็บเป็น `TELEGRAM_BOT_TOKEN` (ไม่มี `VITE_`) |
| ถูกใช้เป็นตัวส่งสแปม | ล็อกปลายทางด้วย `TELEGRAM_ALLOWED_CHAT_IDS` |
| ข้อความขนาดใหญ่ | จำกัดที่ 4,096 ตัวอักษร |
| ข้อมูลผิดรูป | ตรวจชนิดและค่าว่างก่อนส่งต่อ |
| ตั้งค่าไม่ครบ | ปฏิเสธทั้งหมด (ปิดไว้ก่อนปลอดภัยกว่าเปิดทิ้ง) |
| ยิงสแปมรัว ๆ | จำกัด 20 ครั้ง/นาที ต่อ IP |

### ⚠️ ข้อจำกัดที่ยังเหลืออยู่ (ต้องรู้)

**endpoint นี้ยังไม่ตรวจสิทธิ์ผู้เรียก**

คนที่รู้ chat id (ซึ่งดูได้จาก DevTools) ยังส่งข้อความอะไรก็ได้เข้ากลุ่มบริษัทได้
สิ่งที่มีอยู่ตอนนี้เป็นเพียงการ *ลดความเสียหาย* ไม่ใช่ *ปิดช่องโหว่*:

- จำกัดให้ส่งได้เฉพาะกลุ่มที่กำหนด (ส่งเข้าแชทอื่นไม่ได้)
- จำกัดอัตรา 20 ครั้ง/นาที (ยิงรัวไม่ได้)

**ทางแก้ที่แท้จริง:** ต้องตรวจว่าผู้เรียกล็อกอินจริงก่อนส่ง
ซึ่งทำไม่ได้จนกว่าระบบจะมี **Firebase Authentication**
(ปัจจุบันยังใช้รหัสผ่านฝังในโค้ด `1234`/`8888`)

เมื่อติดตั้ง Firebase Auth แล้ว ให้เพิ่มขั้นตอนนี้ใน `api/telegram/send.ts`:
1. รับ ID token จาก header `Authorization: Bearer <token>`
2. ตรวจด้วย Firebase Admin SDK (`verifyIdToken`)
3. ปฏิเสธถ้าตรวจไม่ผ่าน

**หมายเหตุเรื่อง rate limit:** serverless function แต่ละ instance มีหน่วยความจำ
แยกกัน ตัวนับจึงกันได้เฉพาะการยิงรัวจาก instance เดียว ไม่ใช่ทั่วทั้งระบบ
ถ้าต้องการกันจริงจังต้องใช้ที่เก็บกลาง เช่น Vercel KV หรือ Upstash

**สำคัญ:** endpoint นี้เปิดสาธารณะตามธรรมชาติของ serverless function
ถ้าไม่ตั้ง `TELEGRAM_ALLOWED_CHAT_IDS` ใครก็ตามที่เห็น request ใน DevTools
จะคัดลอกไปยิงข้อความเข้าแชทอื่นที่บอทเข้าถึงได้

## ตั้งค่าบน Vercel (จำเป็น ไม่งั้นเว็บจริงส่งไม่ได้)

`.env.local` อยู่แค่ในเครื่อง Vercel มองไม่เห็น ต้องตั้งแยก:

1. เปิด Vercel Dashboard → เลือกโปรเจกต์
2. Settings → Environment Variables
3. เพิ่มสองตัวนี้ (ติ๊ก Production, Preview, Development ทั้งสามช่อง):

```
TELEGRAM_BOT_TOKEN        = <token จาก @BotFather>
TELEGRAM_ALLOWED_CHAT_IDS = -1002778234464
```

4. Save แล้วไปแท็บ Deployments → **Redeploy** ตัวล่าสุด

⚠️ ต้อง Redeploy ด้วย เพราะค่า environment ถูกอ่านตอนรัน function
