# คู่มือจัดการ Telegram Bot Token

## สรุปสั้น ๆ

Token เดิมถูกเขียนไว้ในโค้ดและ **commit ขึ้น git ไปแล้ว** (commit `f7599a4`)
ใครที่เห็นโค้ดนี้ หรือเปิด DevTools ในเบราว์เซอร์ ก็เอา token ไปใช้ได้

**สิ่งที่ต้องทำ: ยกเลิก token เดิมที่ @BotFather — ใช้เวลา ~10 นาที**

---

## เปรียบเทียบให้เห็นภาพ

Token เหมือน **กุญแจบ้าน** ที่ถูกถ่ายรูปลงอินเทอร์เน็ตไปแล้ว

การลบรูปออกไม่ช่วยอะไร เพราะคนที่บันทึกรูปไว้ยังทำกุญแจปลอมได้
**ต้องเปลี่ยนลูกบิดใหม่** = ยกเลิก token เดิมแล้วขอใหม่

---

## ⚠️ ทำไมแค่ย้ายไป .env ไม่พอ

เว็บของเราเป็น **client-side app** โค้ดทั้งหมดรันในเบราว์เซอร์ของผู้ใช้

ค่าจาก `.env.local` จะถูก **ฝังลงไฟล์ JavaScript ตอน build** ผู้ใช้กด F12
เปิดแท็บ Sources ก็อ่านเจออยู่ดี

| วิธี | กัน token หลุดเข้า git | กันผู้ใช้อ่านจากเบราว์เซอร์ |
|---|---|---|
| ฝังในโค้ด (แบบเดิม) | ❌ | ❌ |
| ย้ายไป `.env.local` (ทำแล้ว) | ✅ | ❌ |
| ผ่านเซิร์ฟเวอร์กลาง | ✅ | ✅ |

**สรุป:** สิ่งที่ทำไปคือ *ลดความเสียหาย* ไม่ใช่ *ปิดช่องโหว่*

---

## ขั้นตอนที่ต้องทำเอง (~10 นาที)

### 1. ยกเลิก token เดิม (สำคัญที่สุด)

1. เปิดแอป Telegram
2. ค้นหา **@BotFather** — ต้องมีเครื่องหมายยืนยันสีฟ้า
   ⚠️ มีบอทปลอมชื่อคล้ายกันเยอะ ตรวจให้ดี
3. พิมพ์ `/mybots`
4. เลือกบอทของระบบพาเลท
5. กด **API Token**
6. กด **Revoke current token**
   → token เดิมใช้ไม่ได้ทันที ใครที่ขโมยไปก็ใช้ไม่ได้
7. Telegram จะแสดง **token ใหม่** ให้ — คัดลอกเก็บไว้

### 2. ใส่ token ใหม่ในระบบ

เปิดไฟล์ `.env.local` ที่โฟลเดอร์โปรเจกต์ แล้วใส่ค่า:

```
VITE_TELEGRAM_BOT_TOKEN=ใส่_token_ใหม่_ตรงนี้
```

### 3. รีสตาร์ทเซิร์ฟเวอร์

Vite อ่านไฟล์ `.env` ตอนเริ่มทำงานเท่านั้น ต้องปิดแล้วเปิดใหม่:

```bash
npm run dev
```

### 4. ทดสอบว่าส่งได้

บันทึกรายการเคลื่อนย้าย 1 รายการ แล้วดูว่ามีข้อความเข้า Telegram ไหม

ถ้าไม่เข้า → เปิด DevTools (F12) แท็บ Console ดูข้อความที่ขึ้นต้นด้วย `[Telegram]`

---

## ถ้ายังไม่ใส่ token จะเป็นยังไง

ระบบ **ทำงานได้ปกติทุกอย่าง** แค่ไม่ส่งการแจ้งเตือน Telegram

เราออกแบบให้การแจ้งเตือนล้มเหลวไม่กระทบการบันทึกพาเลท เพราะงานหน้างานสำคัญกว่า

ตอนเปิดเว็บจะเห็นคำเตือนใน Console แค่นั้น

---

## 🔒 ทางแก้ระยะยาว (ปิดช่องโหว่จริง)

ให้ **Firebase Cloud Function** เป็นตัวกลางถือ token แทน

```
ก่อน:  เบราว์เซอร์ ──(มี token)──> Telegram API
                    ↑ ใครก็อ่าน token ได้

หลัง:  เบราว์เซอร์ ──(ไม่มี token)──> Firebase Function ──(มี token)──> Telegram
                                        ↑ token อยู่บนเซิร์ฟเวอร์ อ่านไม่ได้
```

**สิ่งที่ต้องทำ:**

1. เปิดใช้ Cloud Functions (⚠️ ต้องอัปเกรดเป็นแผน **Blaze**)
2. เขียน Function รับ `chatId` + `text` แล้วส่งต่อไป Telegram
3. เก็บ token ด้วย `firebase functions:secrets:set TELEGRAM_BOT_TOKEN`
4. แก้ `telegramService.ts` ให้เรียก Function แทน Telegram API ตรง ๆ
5. จำกัดสิทธิ์ให้เฉพาะผู้ล็อกอินเรียกได้

**ประเมิน:** ~1 วัน

**ข้อควรรู้เรื่องค่าใช้จ่าย:** แผน Blaze คิดตามการใช้งานจริง
Cloud Functions มีโควตาฟรี 2 ล้านครั้ง/เดือน — ระบบขนาดนี้ใช้ไม่ถึง
แต่ต้องผูกบัตรเครดิตไว้ ควรตั้ง budget alert กันไว้

---

## สิ่งที่โค้ดทำไปแล้ว

- ✅ ย้าย token ออกจาก `telegramService.ts` ไปอ่านจาก `.env.local`
- ✅ ระบบไม่พังถ้าไม่มี token (ข้ามการแจ้งเตือนเงียบ ๆ)
- ✅ แจ้งเตือนใน Console ถ้ายังไม่ได้ตั้งค่า
- ✅ แก้บั๊ก `data.description` เป็น undefined แล้วทำให้เกิด TypeError
